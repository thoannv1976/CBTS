# CBTS — AI Admissions Chatbot

Chatbot tư vấn tuyển sinh AI cho trường đại học, xây dựng trên **Next.js 14 + Firebase + Anthropic Claude**, deploy được lên **Google Cloud / Firebase App Hosting**.

## Tính năng

- **Chatbot AI** trả lời câu hỏi tuyển sinh dựa trên kho tri thức của trường (RAG đơn giản, có nguồn dẫn).
- **Trang FAQ công khai** với tìm kiếm, lọc theo nhóm, đếm lượt click cho từng câu hỏi.
- **Tự động tổng hợp FAQ bằng AI**: phân tích các câu hỏi gần đây của người dùng → đề xuất FAQ mới (trạng thái nháp để admin duyệt).
- **Bảng điều khiển quản trị**:
  - Tổng quan thống kê (hội thoại, tin nhắn, lượt xem FAQ, biểu đồ 14 ngày, top FAQ).
  - Quản lý kho tri thức (CRUD + đính kèm tệp lên Firebase Storage).
  - Quản lý FAQ (xuất bản/ẩn, chỉnh sửa, sinh tự động).
  - Xem lại lịch sử hội thoại của người dùng.
- **Đăng nhập Google** (Firebase Auth) cho khu vực quản trị, cấp quyền theo `ADMIN_EMAILS` hoặc collection `admins/{uid}`.
- Giao diện hiện đại với Tailwind CSS, hiệu ứng mượt, dark backgrounds glassmorphism.

## Kiến trúc

```

        Firebase Auth   Firebase Firestore            Anthropic Claude
```

## Cài đặt (local)

```bash
# 1. Clone & cài deps
npm install

# 2. Cấu hình env
cp .env.local.example .env.local
# → Điền NEXT_PUBLIC_FIREBASE_* lấy từ Firebase Console (Project Settings → Web app)
# → Điền ANTHROPIC_API_KEY (https://console.anthropic.com)
# → Điền ADMIN_EMAILS (email Google sẽ được cấp quyền admin)
# → (Tuỳ chọn) FIREBASE_CLIENT_EMAIL + FIREBASE_PRIVATE_KEY của Service Account
#   nếu chạy ngoài Google Cloud. Trên Cloud Run / App Hosting có thể bỏ trống
#   để dùng Application Default Credentials.

# 3. Chạy dev server
npm run dev
```

## Deploy lên Google Cloud (Firebase App Hosting)

App đã có sẵn `apphosting.yaml`. Sau khi cài Firebase CLI:

```bash
firebase apphosting:backends:create     # chỉ cần lần đầu
firebase apphosting:secrets:set ANTHROPIC_API_KEY
firebase apphosting:secrets:set ADMIN_EMAILS
firebase apphosting:secrets:set NEXT_PUBLIC_FIREBASE_API_KEY
firebase apphosting:secrets:set NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
firebase apphosting:secrets:set NEXT_PUBLIC_FIREBASE_APP_ID
git push                                # App Hosting auto-build & deploy
```

App Hosting sử dụng Cloud Run dưới nền và tự gắn Service Account, do đó
Firebase Admin SDK không cần khoá riêng.

## Cấu trúc Firestore

| Collection           | Mô tả                                                                 |
|----------------------|----------------------------------------------------------------------|
| `knowledge/{id}`     | Mục tri thức (title, category, content, tags, fileUrl, updatedAt)    |
| `faqs/{id}`          | FAQ (question, answer, category, clickCount, published, autoGenerated) |
| `conversations/{id}` | Metadata hội thoại                                                    |
| `conversations/{id}/messages/{msgId}` | Từng tin nhắn (role, content, createdAt)             |
| `stats/{YYYY-MM-DD}` | Bộ đếm theo ngày: conversations, messages, faqClicks                  |
| `admins/{uid}`       | Đánh dấu user có quyền quản trị (tự cấp khi email nằm trong ADMIN_EMAILS) |

## Cấp quyền admin

Hai cách:

1. **Email allowlist (đơn giản nhất)**: thêm email vào biến môi trường
   `ADMIN_EMAILS` (phân tách bằng dấu phẩy). Khi user đó đăng nhập, hệ
   thống sẽ tự tạo document `admins/{uid}` lần đầu.
2. **Thủ công**: tạo document `admins/{uid}` trong Firestore với các
   trường tuỳ ý (email, name, …). Firestore rules dựa vào sự tồn tại
   của document này để cấp quyền.

## Bảo mật

- Toàn bộ thao tác ghi vào `knowledge`, `faqs`, đọc `conversations` đều
  qua API server với xác thực Firebase ID token + kiểm tra admin.
- Firestore rules chặn client thường truy cập các collection nhạy cảm.
- Storage rules chỉ cho admin upload, giới hạn ≤ 20 MB và content type.
